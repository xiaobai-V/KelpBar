# 08_Fifo -- 命名管道（FIFO）

## 模块职责

学习命名管道（FIFO / mkfifo）实现进程间通信。与 07 模块的匿名管道不同，命名管道存在于文件系统中，可用于无亲缘关系的进程间通信。本模块演示了 mkfifo 创建、读写端分离、缓冲区管理、循环读取等关键技术。

## 入口与启动

- **入口文件**：`main.c` -- 在同一程序内 fork 出父子进程模拟命名管道通信

### 编译与运行

```bash
mkdir -p build && cd build
cmake ..
make
./main
```

本模块为独立演示程序，无对外接口。

## 数据模型

### 数据流

```
父进程 --[O_WRONLY write]--> /tmp/my_fifo --[O_RDONLY read]--> 子进程
```

### 代码演进记录（源码注释）

1. 父进程用 `O_RDWR` 打开 FIFO 导致死锁 -- 改为 `O_WRONLY`
2. 子进程读缓冲区未预留 `\0` 位置 -- 改为 `sizeof(read_buf) - 1`
3. 缓冲区太小（10 字节）导致数据截断 -- 改为循环读取

## 常见问题 (FAQ)

**Q: 为什么父进程不能用 O_RDWR 打开 FIFO？**
A: FIFO 的 open 是阻塞的。如果用 O_RDWR 打开，读端和写端都指向自己，内核认为写端已就绪，`open` 不会阻塞等待对端，可能导致后续 `read`/`write` 行为异常（死锁或非预期行为）。

**Q: 多次运行时为什么需要先 unlink？**
A: `mkfifo` 在路径已存在时会失败。每次运行前 `unlink` 清除上次残留的 FIFO 文件。

**Q: 为什么写入时不需要 `strlen + 1` 包含 `\0`？**
A: FIFO 传输的是原始字节流，不是字符串。读端通过 `read` 返回值知道实际读取了多少字节，手动添加 `\0` 即可。
